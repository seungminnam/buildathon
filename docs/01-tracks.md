## 1. RWX: Blast Radius

- **문제:** sqlglot(Python SQL 파서)에 대한 패치마다 어떤 테스트를 돌릴지 고르고, 최대 8개 워커에 나눠요.
- **입력:** `/data/commits/<id>.patch`, `/data/tests.json` (테스트 번호, 파일 경로, 기록된 실행 시간). sqlglot 기준 커밋은 `eb11aec4be8cb2122afe713a4816662c3f0fb2fa`.
- **출력:** 커밋마다 JSON 한 줄. 예: `{"commit":"k7q2","workers":[[12,845],[3,77]]}`. 아무것도 안 돌리려면 `[]`.
- **비용 계산:** 가장 바쁜 워커의 테스트 초 + 워커당 2초. 실패할 테스트를 하나라도 빠뜨리면 **+300초**. 프로그램 CPU 초도 더해져요. 3회 실행해서 중간값을 써요.
- **제한:** repo 20 MB 이하. 빌드는 4코어, 8 GB, 10분, 네트워크 있음. 실행은 2코어, 4 GB, 3분(파이널은 4.5분), 네트워크 없음.
- **허용:** 고정 커밋 기준으로 만든 coverage, import, fixture 맵. **금지:** 패치를 보고 미리 계산해 둔 답을 찾아 쓰는 표.
- **중요:** **파이널만 점수에 들어가요.** 처음 보는 커밋, 새로운 종류의 변경으로 채점하고, 연습 보드에는 상금이 없어요. 파이널에서는 1위와 1초 이내 차이면 동점으로 보고 먼저 제출한 팀이 이겨요.
- **스타터:** `blast-radius-sample.tar.gz` (샘플 30개, 로컬 채점기, `make sample`). 필요한 것: Docker, make, Python 3.9+.
- **판단:** 노트북으로 할 수 있고 로컬 채점기도 있어요. 연습 보드 순위가 의미 없어서 늦게 시작해도 불리하지 않아요. 핵심은 coverage 맵(어떤 소스 줄이 어떤 테스트에 쓰이는지)과, 놓쳤을 때 300초를 무는 위험 사이의 균형이에요.

## 2. Machina: CAD De-ID

- **문제:** 188,722개 파일, 139.7 GB(PDF, 도면, SolidWorks/Inventor, 중립 CAD 포맷, 이미지, 압축 파일)에서 회사명, 사람 이름, 계정, 연락처, 도메인, 주소, 로고, 프로젝트명과 부품명/번호를 **일관된 가명**으로 바꿔요. 파일은 계속 쓸 수 있어야 하고 파일 간 참조도 유지돼야 해요.
- **범위:** 보이는 텍스트와 이미지, 파일/폴더 이름, PDF 메타데이터와 첨부, 네이티브 CAD 속성, 내장 미리보기, 압축 파일 내부까지.
- **보존해야 할 것:** 형상, 치수, 공차, 단위, 재질, 구성, BOM, 도면-모델-어셈블리 간 링크.
- **제출:** `attempt-N/{corpus/, code/, README.txt}`를 `upload.py`로 GCS 팀 폴더에 올리고 경로를 제출해요.
- **채점:** 비공개 체크 1,000개. 카테고리별 통과 수만 알려주고, 채점에 최대 3시간 걸려요. **총 20회**. 마감 시점 리더보드가 그대로 최종 결과예요.
- **현실적인 제약:** 400 GB 이상 디스크가 필요하고, 느린 회선이면 클라우드 VM을 직접 빌려야 해요. 원본 데이터는 비공개로 유지해야 해요.
- **보너스:** 상위 3팀은 Machina 1차 면접에 추천돼요.
- **판단:** 팀이 가장 적고(89) 점수 차이도 커요. 대신 인프라 부담(다운로드, 디스크, 비용)과 제출 주기가 느린 게 큰 리스크예요. CAD 포맷(SolidWorks/Inventor 내부 메타데이터) 경험이 있으면 유리해요.

## 3. Databricks: Shopping Sessions

- **문제:** 지저분한 CSV 로그(중복, 깨진 줄, 잘못된 타임스탬프, 늦게 온 이벤트)를 정리하고, 사용자 ID를 연결하고(긴 체인, 공유 기기), 세션을 만들고, 광고 클릭 attribution과 지난 7일 assist를 계산해서 `/output/user_daily/`, `/output/campaign_daily/` Parquet 두 개를 만들어요. **정확히 맞아야 하고**, 조금이라도 틀리면 0점이에요.
- **점수:** 컨테이너 실행 시간. 연습은 약 2천만 이벤트, 파이널은 약 6천만 이벤트이고, 파이널에서 한 번이라도 3분을 넘기면 점수가 없어요.
- **제한:** 8 vCPU, 24 GB, linux/amd64, 이미지 8 GB 이하, 실행 시 네트워크 없음.
- **스타터:** PySpark, DuckDB, Polars 중 선택. 엣지 케이스 fixture 36개, 1M dev 세트 생성기, `make check-dev`.
- **판단:** 리더보드가 이미 0.3–0.9초대에 몰려 있어서 사실상 포화예요. 동점이면 먼저 낸 팀이 이기니까 지금 시작하면 1등은 어려워요.

## 4. Builders: Mech Royale

- **문제:** OSU Oval 맵에서 16명이 싸우는 3D 배틀로얄의 메카 AI를 만들어요. 킬 수가 아니라 순위가 점수예요.
- **인터페이스:** stdin/stdout으로 `mechfight/1` JSON 라인 (`briefs/builders-protocol.md`). 관측마다 **50ms 안에** 응답해야 해요. 1 CPU, 512 MB, 네트워크 없음.
- **연습:** 하우스 봇 15개(한 팀처럼 협력하고, 약한 상대부터 사냥)와 48판. **파이널:** 상위 32팀이 예선 16판, 상위 16팀이 64판 시리즈.
- **스타터:** `mechfight-kit.tar.gz` (Python/TS 봇, `check/check.py`). 브라우저에서 직접 해볼 수 있어요: https://play.joinbuilders.org
- **판단:** 재밌고 피드백이 빨라요(시간당 4회). 하지만 상위권이 촘촘하고(5.8–6.3) 파이널이 대전이라 운의 영향이 커요.
