Run less and you win; miss a failure and it costs you.From RWXDan Manges, co-founder and CEO of RWXThe problemEvery fast CI system has to decide which tests a commit needs. Run them all and you wait; skip the wrong one and a bug ships.You get a batch of code changes to sqlglot, a Python SQL parser. For each change, say which of its tests to run and how to split them across up to 8 workers.Most changes break at least one test. Some break nothing at all, and the right answer for those is to run nothing.Get startedDownload blast-radius-sample.tar.gz below and unpack it into an empty folder (it has no top-level folder). You need Docker, make, and Python 3.9 or newer.Run make sample to build the starter image, run it under the limits below on the 30 sample commits, and score what it printed.What to hand inSubmit a public GitHub repository with a Dockerfile at its top, and the commit to score. Any language, any libraries, and any amount of AI are allowed.Every change your program receives is a patch against sqlglot at commit eb11aec4be8cb2122afe713a4816662c3f0fb2fa. Each one stands alone./data/commits/<id>.patch holds one unified diff per commit./data/tests.json lists every test, numbered, with its file path and recorded runtime in seconds.Print one JSON line per commit to stdout: {"commit": "k7q2", "workers": [[12, 845, 901], [3, 77]]}. Each inner list is one worker's test numbers, and "workers": [] runs nothing.Send logs to stderr. Any other output on stdout, or more than 2 MB on stdout, rejects the run.How it is scoredA commit costs the recorded test seconds of its busiest worker plus 2 seconds for every worker, up to 8 workers, and running nothing costs 0.A commit whose selection leaves out any test that fails on it adds 300 seconds.Your program's CPU seconds are added to the total, and running sqlglot's tests while you decide is allowed and charged here.Your image runs 3 times, and the middle total counts, rounded to 0.1 s.What fails meansA test fails on a commit when pytest reports a failure, an error, or a timeout for it, or when its file cannot be imported. A test with subtests is one test, and one failing subtest fails it.A change that only adds a comment is not promised to be harmless.LimitsYour repository may hold at most 20 MB. Git submodules and Git LFS files are not fetched, so clone sqlglot in your Dockerfile and commit maps as plain files.Builds have network access, 4 cores, 8 GB of memory, and 10 minutes. You may install sqlglot and run its tests during the build to make coverage or import maps.Every submission is built from nothing, so a build that runs sqlglot's tests takes minutes each time you submit. A map you make once and commit builds in seconds.Runs have no network access, 2 cores, 4 GB of memory, and 3 minutes for the whole batch (4.5 minutes in the final, which has about 1.5x as many commits).Your program runs as user nobody with HOME=/tmp, a read-only disk, an empty 64 MB /tmp, and at most 256 processes.Docs and starter filesSCORING.mdDownloadExact scoring rules: input files, stdout format, worker costs, miss penalties, and CPU time (also inside blast-radius-sample.tar.gz).blast-radius-sample.tar.gzStarter kit: a working selector, 30 sample commits with the tests each one breaks, and the local scorer.ScoringMetricSimulated CI seconds, lower is betterBaseline to beat1614.1 s (Starter: run every test, split across 3 workers)Formulabusiest worker test seconds + 2 s per worker + 300 s per missed commit + CPU seconds; middle of 3 runsTiesEqual scores rank the earlier submission first. In the final, scores at most 1 second behind the best tie and rank earliest first, and the remaining entries group the same way from the next best. First place wins.Scorer versionblast-radius-1For each commit, you pay the busiest worker's recorded test seconds plus 2 seconds per worker, and 300 seconds if you leave out any failing test; your program's CPU seconds are added across the batch. With your score you are told each run's simulated seconds, CPU seconds, and how many commits missed, never which.RulesPrint one JSON line per commit, with at most 8 workers, no duplicate test in a commit, and only test numbers from tests.json.A broken rule, crash, timeout, memory limit overrun, or failed build rejects the submission with the reason and never changes your best score.You never see what your program printed on practice or final runs. Debug locally on the sample set with make sample.Your team may submit once an hour to start. We raise the limit if the queue stays short.One team a person, and your own team's repository. No sharing code between teams: top entries are compared, and you may be asked to explain yours. A submission with the same repository, commit or archive as another team's is disqualified, the later one.Your build may download only from public package registries (PyPI, npm, Docker Hub), GitHub releases at a fixed tag, and sqlglot at commit eb11aec. Nothing from an address your team controls, because the final rebuilds every image after the cutoff.No answers worked out ahead of time and looked up by patch: no table from a patch, or from a kind of edit, to the tests it breaks. Maps built from the pinned commit (coverage, imports, fixtures) are allowed. Top entries are read.Keep your repository public, with every commit you submitted still in it, until results are published. An entry we cannot fetch or restore for the final scores nothing.Only the final counts. The practice board carries no prize.If we find a mislabeled commit before results are published, we correct it for every team.The finalAt the cutoff, your chosen commit (your best, unless you pick another) is scored on unseen commits, including kinds of change not in practice. At least the top 5 entries are then scored again on those same commits, 5 runs each instead of 3, one at a time on one idle machine; that middle total replaces their first score.The cutoff is Sun 11:00 AM EST.Sign in to submit.Blast Radiusby RWX · $5,000 prize · 276 teamsSimulated CI seconds, lower is better.
